## Merge damage to be aware of

The `32c7818` merge **reverted several refactors** to develop's monolithic versions while leaving the refactored infra unused beside them:
- `auth.service.ts` — now Prisma-direct, 970 lines (was a 91-line `AUTH_REPOSITORY` stub). `IAuthRepository`/`PrismaAuthRepository` sit unused.
- `AdminController` — injects monolithic `AdminService` (2929 lines) instead of the extracted `AdminAnalyticsService`/`AdminUserService`/etc. (which still exist and pass their own specs).
- `user.service.ts`, `notification.service.ts` — Prisma-direct, standard NestJS exceptions instead of domain exceptions.

Treat the merged monoliths as feature-complete/intended for now; re-extraction (if desired) is a separate refactor decision per module.

### Per-module execution recipe

For each module: `git diff integration origin/develop-v1.2.0 -- src/<module>` → identify develop's genuinely-new logic (ignore un-extracted duplicates of what integration already extracted) → place into the matching extracted service/repository → fix that module's spec to match → `pnpm build` + module tests → commit.

## Recommended order

1. Small/self-contained first to establish the recipe: **parent-favorites** or **health**.
2. Then feature-bearing mediums: **voice**, **admin**, **notification**.
3. Then the large cores: **story**, **auth** (also re-decide monolith-vs-re-extract here).
4. Finally **shared** + top-level (`main.ts`, `app.module.ts`) cleanup.

Reconcile schema changes first if any module needs them (run `npx prisma generate` after; the editor LSP lags — trust `npm run build`).
